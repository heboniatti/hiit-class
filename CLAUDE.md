# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

This is the **Laravel React starter kit** (Laravel 13 + Inertia v3 + React 19 + Tailwind v4), currently unmodified apart from its name. The only model is `User`; there is no HIIT domain code yet. Treat the existing auth/settings slice as the reference for conventions when adding features.

## Commands

Composer scripts wrap most workflows — prefer them over raw tool invocations:

| Command | What it does |
| --- | --- |
| `composer setup` | First-time install: deps, `.env`, key, migrate, npm install, build |
| `composer dev` / `php artisan dev` | Run all dev processes (server, queue, logs, vite) |
| `composer test` | `config:clear` + Pint check + PHPStan + `artisan test` |
| `composer ci:check` | Everything `composer test` does, plus JS lint/format/type checks — mirrors GitHub Actions |
| `composer lint` | `pint --parallel` (fix); `composer lint:check` to verify only |
| `composer types:check` | `phpstan analyse` (Larastan, **level 7**, over `app/ bootstrap/app.php config/ database/ routes/`) |
| `npm run lint` / `format` / `types:check` | ESLint fix, Prettier write, `tsc --noEmit` |
| `npm run build:ssr` | Client + SSR bundle |

Run a single test: `php artisan test --compact --filter=testName` or pass a path.

CI runs `composer setup && composer ci:check` on PHP 8.5 / Node 22, so `composer ci:check` locally is the definitive pre-push check.

## Architecture notes

**Auth is headless Fortify.** There are no auth controllers in `app/` — Fortify registers the routes, and `FortifyServiceProvider::configureViews()` binds each one to an Inertia page (`auth/login`, `auth/reset-password`, `auth/forgot-password`). Only the `reset-passwords` feature is enabled in `config/fortify.php`: registration, email verification, and 2FA are **off**, even though `verified` middleware and `TwoFactorAuthenticationRequest` exist in the tree. Enable features there, not by hand-writing routes. Login throttling is a custom `login` rate limiter (5/min per email+IP) in the same provider.

**Layouts are assigned globally, not per page.** `resources/js/app.tsx` resolves the layout from the page name: `welcome` → none, `auth/*` → `AuthLayout`, `settings/*` → `[AppLayout, SettingsLayout]`, everything else → `AppLayout`. New pages get their layout by living in the right directory — don't wrap a page in its own layout.

**Wayfinder output is generated and gitignored.** `resources/js/actions/`, `resources/js/routes/`, and `resources/js/wayfinder/` are rebuilt by the Vite plugin (`formVariants: true`) or `php artisan wayfinder:generate`. Never edit them; import from `@/actions/…` and `@/routes/…`. They won't exist on a fresh clone until dev/build runs.

**Toasts flow through Inertia flash.** Controllers call `Inertia::flash('toast', ['type' => 'success', 'message' => __('…')])`; the `use-flash-toast` hook listens for the `flash` event and forwards to sonner, whose `<Toaster />` is mounted in `app.tsx`. Follow this instead of returning ad-hoc props.

**Validation rules live in traits.** `app/Concerns/ProfileValidationRules.php` and `PasswordValidationRules.php` are consumed by FormRequests in `app/Http/Requests/Settings/`. Extend the trait rather than inlining rules in a request.

**Password rules are environment-dependent.** `AppServiceProvider::configureDefaults()` sets `Password::defaults()` to a strict policy **only in production** (null locally), plus `CarbonImmutable` dates and `DB::prohibitDestructiveCommands()` in prod. Controllers pass `Password::defaults()->toPasswordRulesString()` to the frontend as a `passwordRules` prop, so the client mirrors whatever the environment enforces.

**Theme/sidebar state rides on unencrypted cookies.** `appearance` and `sidebar_state` are excluded from cookie encryption in `bootstrap/app.php`. `HandleAppearance` shares `appearance` with the Blade root view (avoiding a flash of wrong theme); `HandleInertiaRequests` shares `name`, `auth.user`, and `sidebarOpen` with every page.

**Routing.** `routes/web.php` (home, dashboard) requires `routes/settings.php`. View-only pages use `Route::inertia()` — no controller needed.

## Conventions

- SQLite at `database/database.sqlite`; sessions, cache, and queue all use the `database` driver.
- Tests: Pest 4. `tests/Pest.php` applies `RefreshDatabase` to `Feature` only — Unit tests get no DB.
- UI is shadcn/ui (new-york style, neutral base, lucide icons) in `resources/js/components/ui/`. Check there before writing a component.
- `@/*` maps to `./resources/js/*`.
- The React Compiler (`babel-plugin-react-compiler`) is enabled — avoid manual `useMemo`/`useCallback` unless profiling says otherwise.
- ESLint enforces blank lines around control statements via `@stylistic`; let `npm run lint` fix formatting rather than hand-tuning.

# Inertia v3

- Use all Inertia features from v1, v2, and v3. Check the documentation before making changes to ensure the correct approach.
- New v3 features: standalone HTTP requests (`useHttp` hook), optimistic updates with automatic rollback, layout props (`useLayoutProps` hook), instant visits, simplified SSR via `@inertiajs/vite` plugin, custom exception handling for error pages.
- Carried over from v2: deferred props, infinite scroll, merging props, polling, prefetching, once props, flash data.

- `Inertia::lazy()` / `LazyProp` has been removed. Use `Inertia::optional()` instead.
- Prop types (`Inertia::optional()`, `Inertia::defer()`, `Inertia::merge()`) work inside nested arrays with dot-notation paths.
- SSR works automatically in Vite dev mode with `@inertiajs/vite` - no separate Node.js server needed during development.
- Event renames: `invalid` is now `httpException`, `exception` is now `networkError`.
- `router.cancel()` replaced by `router.cancelAll()`.
- The `future` configuration namespace has been removed - all v2 future options are now always enabled.
